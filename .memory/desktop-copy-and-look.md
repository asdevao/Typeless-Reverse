桌面端（Electron 主窗口、首次引导）的两条要求，2026-10-15 他看过第一版之后说的：

1. 文案太啰嗦。原话："整个桌面端 app 的文案都需要改，现在太啰嗦了，咱们要简短干练，尽可能不要使用完整的主谓宾句子，短词短句"。
2. 界面别完全照抄 Typeless。原话："ui 也不要照抄 typeless 完全，比如 app 的 ui token 做成可以切换的吗，根据咱们 cli theme 的主题色去做好看的 app 颜色，做一些高审美的渐变、玻璃啥的，做点特色，不一样的东西"。

**Why:** 第一版照原版做得很像（灰底、黑白、长句说明），他要的是"功能和结构对齐原版、观感是自己的"。

**How to apply:**
- 界面上的字：标题、按钮、说明都用书面语的短词短句（"已保存"、"未配置密钥"、"按 右⌥ 说话"），能删的解释删掉，细节放悬停提示。命令行的说法不在这次要求里。
- 配色从 src/themes 的主题出发（墨、朱砂、靛青……），主窗口跟着换主题当场变；可以加主题 token，但要过 src/themes/contract.mjs 的对比度检查。
- 渐变、毛玻璃（backdrop-filter、Electron 的 vibrancy）可以用，要有节制、做出辨识度，不要退回原版的纯灰白。
- 功能范围仍然是原版有的才做（[[typeless-clone-scope-dictation]]）。
- 2026-10-16 又说了两条：检查的结果通过时只写结论，不要附带转出来的原文、耗时（原话"不要再讲后面那一串……这种屁话"）；不通过照样说清原因。同日稍晚又否了"能用"这个词："要讲书面语，简洁干练，不要讲陈述句，不要讲什么'能用'这种这么低级的语言"，样式也不能"就换了个颜色的字"。现在通过写"检测通过"、用带图标的淡底徽标，失败用说明框；词表和写法以模型广场原型旁的规范页为准（[[speakmore-model-plaza]]）。列表里各行的文字要对齐，按钮数不同的行别让状态文字参差不齐（他一眼就看出来了），截图验收时专门量一下各行的边缘。
- 2026-10-16 又说：整个 App 的字"没有层级"、"太平了"——名字、标签、说明、实测数都一样大。已改成字号七档（40/28/22/18/15/13/11）、字重四档，样式里只用 tokens.css 的变量（有测试守着）；重要的数（均分、速度、内存）用数值加粗、单位和名目小一档的样式单独摆，标签用带底色的小胶囊，状态带小圆点。以后加界面照这套角色挑字号，别再写 12、14 这种夹在中间的数。
- 2026-10-17 他截图问"怎么退回到那种前端初学者的样式了"：首页的时段按钮样式被删、退回灰底凸边的系统按钮，同类的还有"获取密钥"。改样式、删样式之后要在真窗口里把每个按钮查一遍（拿计算样式和 `all: revert` 的按钮比，看是不是还是系统外观），别只看改到的那一页；window.css 的 :where(button) 底子不能删（有测试）。浏览器自带的表单校验气泡也不用（跟着系统语言、样子是系统的），表单加 novalidate，由主进程按界面语言说。
- 2026-10-17 他说首次引导是门面，要和主窗口一样高审美、图标丰富，按钮输入框不能像初学者写的；引导必须能前进后退、每一步都能跳过进去再配（数据隐私不要 key）。已重做成"先选识别方式 → 准备"，厂商一家一行、选中就地展开，密钥输入是带图标和粘贴按钮的一整块；改界面后浅色、深色、彩色主题各截一遍图再交。
- 2026-10-17 推荐组合先做成两两一排的卡片，他说"做成下拉选择的吧，不然又容易因为数量问题而出现 ui 不对齐的情况"。数量会变的一组东西，用一项一行的列表或浮层选单，不用按列数排的卡片网格。
